# 공개·관리자 사이트맵과 권한 구조

작성일: 2026-09-21
상태: 설계 초안 / 구현 전
기준: [첫 납품 범위와 합격 기준](first-delivery.md)의 소규모 공공기관 대표 홈페이지.

메뉴명과 URL은 초기 제안이다. 기존 Next.js 라우트를 그대로 확정하는 문서가 아니며 Vue 앱 구성 결정 후 실제 라우팅에 반영한다.

## 1. 공개 홈페이지

```text
홈
├── 기관 소개
│   ├── 기관 안내
│   └── 오시는 길·연락처
├── 사업 안내
│   ├── 사업 목록
│   └── 사업별 안내
├── 알림·자료
│   ├── 공지사항 → 목록·검색 → 상세·첨부
│   └── 자료실   → 목록·검색 → 상세·첨부
└── 이용 안내 (푸터에서도 접근)
    ├── 개인정보 처리방침
    ├── 저작권 정책
    └── 사이트맵
```

사업 목록은 개발자가 설정한 고정 페이지와 링크로 구성한다. 별도 사업 데이터 관리 기능은 추가하지 않는다. 오시는 길은 주소·교통 안내 본문과 외부 지도 링크로 시작한다. 지도 서비스 연동과 영상 콘텐츠는 첫 범위에 넣지 않는다.

| 화면 ID | 화면 | URL 제안 | 운영 방식 / 기능 연결 |
| --- | --- | --- | --- |
| P01 | 홈 | `/` | 고정 레이아웃, 소개·링크는 관리 콘텐츠, 최근 공지는 게시본 자동 조회 / F02 |
| P02 | 기관 안내 | `/about/overview` | 고정 페이지 편집 / F03 |
| P03 | 오시는 길·연락처 | `/about/location` | 고정 페이지 편집 / F03 |
| P04 | 사업 목록·안내 | `/business`, `/business/:slug` | 사전 구성 페이지의 내용 편집 / F03 |
| P05 | 공지 목록·검색 | `/board/notices` | 제목 검색·페이지 이동 / F04 |
| P06 | 공지 상세 | `/board/notices/:id` | 게시본·첨부 조회 / F04 |
| P07 | 자료실 목록·상세 | `/board/resources`, `/board/resources/:id` | 공지와 동일한 게시판 유형 / F04 |
| P08 | 정책 페이지 | `/policy/privacy`, `/policy/copyright` | 기관이 제공·확인한 내용 게시 / F03 |
| P09 | 사이트맵 | `/sitemap` | 공개 메뉴 기준 자동 구성 / F01 |
| P10 | 공통 오류·빈 결과 | 해당 요청 위치 | 없는 페이지, 검색 결과 없음, 서버 오류 / F12 |

### 공개 탐색 규칙

- 공통 헤더·푸터·본문 바로가기·현재 위치를 제공한다. 모바일에서도 같은 정보 구조를 유지한다.
- 제목 검색은 각 게시판 내부 검색이다. 사이트 전체 통합검색은 첫 범위에 포함하지 않는다.
- 검색어·페이지 번호를 URL에 유지해 상세에서 돌아왔을 때 목록 맥락을 복원한다.
- 메뉴 숨김은 탐색 설정이다. 게시된 페이지는 메뉴에서 숨겨도 직접 URL 접근이 가능하다. 비공개 전환은 반드시 게시 중단으로 처리한다.
- 미게시 페이지는 메뉴·홈 링크·사이트맵에서 제외한다. 외부 링크와 게시판 링크는 목적지 유형별로 검증한다.
- 없는 글과 방문자에게 비공개인 글은 공개 응답에서 내부 상태를 노출하지 않는다.

## 2. 관리자 CMS

```text
로그인
관리자
├── 시작 화면
├── 게시글 관리
│   ├── 공지사항
│   └── 자료실
│       └── 작성·수정 → 미리보기 → 게시
├── 페이지 관리
│   └── 사전 구성 페이지 → 내용 편집 → 미리보기 → 게시
├── 파일 관리
├── 휴지통
├── 사이트 설정 [기관 관리자]
│   ├── 기관 정보·푸터
│   └── 메뉴명·순서·표시
├── 계정 관리 [기관 관리자]
├── 변경 기록 [기관 관리자]
└── 내 계정·비밀번호 변경 / 로그아웃
```

시작 화면은 최근 수정 콘텐츠와 작업 바로가기로 제한한다. 방문 통계·차트·성과보고서는 후속이다.

| 화면 ID | 화면 | URL 제안 | 주요 작업 / 기능 연결 |
| --- | --- | --- | --- |
| M01 | 로그인 | `/admin/login` | 인증·오류 안내·초기 비밀번호 변경 유도 / F05 |
| M02 | 시작 화면 | `/admin` | 최근 수정과 작업 바로가기 |
| M03 | 게시글 목록 | `/admin/posts?board=notices` | 게시판·상태 필터, 제목 검색, 글 작성 / F07 |
| M04 | 게시글 편집 | `/admin/posts/new`, `/admin/posts/:id/edit` | 초안·리비전 편집, 첨부·검증·게시 / F07~F09 |
| M05 | 페이지 목록·편집 | `/admin/pages`, `/admin/pages/:id/edit` | 허용 필드와 블록 내용 편집 / F03·F07·F08 |
| M06 | 미리보기 | `/admin/preview/:type/:id` | 로그인한 편집 권한자만 초안 보기 / F07 |
| M07 | 파일 목록·상세 | `/admin/media` | 업로드·사용처 확인·미사용 파일 제거 / F09 |
| M08 | 휴지통 | `/admin/trash` | 삭제된 글·페이지 조회와 초안 복원 / F07 |
| M09 | 사이트 설정 | `/admin/settings` | 기관명·로고·연락처·푸터 / F10 |
| M10 | 메뉴 설정 | `/admin/menus` | 사전 구성 메뉴의 명칭·순서·표시 / F10 |
| M11 | 계정 목록·편집 | `/admin/users`, `/admin/users/:id` | 발급·역할 지정·비활성화·비밀번호 초기화 / F06 |
| M12 | 변경 기록 | `/admin/audit` | 수행자·시각·대상·행동 조회 / F11 |
| M13 | 내 계정 | `/admin/account` | 본인 비밀번호 변경, 본인 역할 조회 / F05 |

계정 초기화는 일회성 초기 비밀번호 등 정해진 절차로 수행하고 최초 로그인 시 변경한다. 이메일 발송·셀프 가입·비밀번호 찾기 서비스는 별도 범위다. 운영자가 기존 비밀번호를 조회하는 기능은 제공하지 않는다.

## 3. 역할과 권한

첫 제품의 로그인 역할은 **기관 관리자와 콘텐츠 담당자 두 가지**다. 콘텐츠 담당자는 해당 사이트의 모든 게시판·페이지를 공동 관리하는 것으로 제안한다. 작성자별·부서별 권한 분리는 후속 범위다.

| 작업 | 방문자 | 콘텐츠 담당자 | 기관 관리자 |
| --- | --- | --- | --- |
| 게시된 페이지·글·공개 첨부 조회 | 가능 | 가능 | 가능 |
| 모든 콘텐츠 초안 조회·편집·미리보기 | 불가 | 가능 | 가능 |
| 글 작성·게시·게시 중단·재게시 | 불가 | 가능 | 가능 |
| 사전 구성 페이지 내용 편집·게시 | 불가 | 가능 | 가능 |
| 일반 콘텐츠 휴지통 이동·초안 복원 | 불가 | 가능 | 가능 |
| 보호 페이지 게시 중단·휴지통 이동 | 불가 | 불가 | 불가 — 대체 연결을 포함한 개발 작업 |
| 허용 파일 업로드·사용처 조회 | 불가 | 가능 | 가능 |
| 미사용 파일 제거 | 불가 | 가능 | 가능 |
| 게시·초안·휴지통 리비전에서 참조 중인 파일 제거 | 불가 | 불가 | 불가 |
| 기관 정보·메뉴 설정 | 불가 | 불가 | 가능 |
| 계정 발급·역할 변경·비활성화·초기화 | 불가 | 불가 | 가능 |
| 본인 비밀번호 변경 | 불가 | 가능 | 가능 |
| 전체 변경 기록 조회 | 불가 | 불가 | 가능 |
| 변경 기록 수정·삭제 | 불가 | 불가 | 불가 |
| 페이지 구조·테마·게시판 유형 추가 | 불가 | 불가 | 불가 — 개발 작업 |
| 서버 배포·백업·복구 | 불가 | 불가 | 불가 — 운영 절차 |

홈·기본 정책·필수 안내처럼 납품 구성에서 보호 대상으로 지정한 페이지는 임의 게시 중단·삭제를 막는다. 일반 페이지와 구분하여 목록에 안내한다. 구체적인 보호 목록은 사이트 초기 설정에 기록한다.

납품 개발자는 별도 상시 CMS 최고권한 계정으로 두지 않는다. 서버 운영 권한과 CMS 계정을 분리하고, CMS 지원이 필요할 때 기관 관리자가 기간·목적을 정해 계정을 발급한다. 유지보수 종료 후 회수한다.

### 권한 적용 원칙

- UI의 메뉴·버튼 숨김과 별개로 서버에서 요청·대상·행동마다 권한을 확인한다.
- 사용자 ID·역할을 요청 본문 값만으로 신뢰하지 않는다. 로그인된 주체와 서버 데이터로 판정한다.
- 마지막 활성 기관 관리자의 비활성화·강등은 거부한다. 역할 변경·비활성화는 기존 세션에도 반영한다.
- 미리보기는 추측하기 어려운 URL만으로 보호하지 않는다. 초안과 파일 요청마다 권한을 확인하며 공개 캐시에 저장하지 않는다.
- 영구 콘텐츠 삭제 UI는 첫 범위에서 제외한다. 보관 기간·정리 절차는 기관 정책에 따라 운영 문서에서 정한다.

## 4. 콘텐츠 상태와 공개 리비전

콘텐츠 상태와 편집 중인 변경을 별도로 관리한다. 사용자가 보는 상태는 `초안 / 게시 중 / 게시 중단 / 휴지통`이며, 게시 중 수정본이 있으면 `미게시 변경 있음`을 추가 표시한다.

| 현재 상태 | 행동 | 결과 | 공개 사이트 |
| --- | --- | --- | --- |
| 새 콘텐츠 | 초안 저장 | 초안 리비전 생성 | 보이지 않음 |
| 초안 | 게시 | 검증된 리비전 게시 | 게시본 노출 |
| 게시 중 | 수정 저장 | 편집 리비전만 갱신 | 기존 게시본 유지 |
| 게시 중·수정 있음 | 재게시 | 공개 리비전을 원자적으로 교체 | 새 게시본 노출 |
| 게시 중 | 게시 중단 | 게시 중단 | 목록·직접 조회 모두 차단 |
| 게시 중단 | 게시 | 현재 편집 리비전 검증 후 공개 | 게시본 노출 |
| 초안·게시 중·게시 중단 | 휴지통 이동 | 휴지통 | 보이지 않음 |
| 휴지통 | 복원 | 초안 | 자동 공개하지 않음 |

보호 페이지에는 게시 중단·휴지통 전이를 적용하지 않는다. 게시 전 검사 실패 시 상태가 바뀌지 않고 기존 게시본을 유지한다. 오래된 버전 저장·게시 요청은 충돌로 거부하며 새 내용을 확인하도록 안내한다.

파일은 현재 공개 리비전의 참조 여부로 공개 접근을 판정한다. 초안 전용 파일은 비공개이며, 같은 파일을 다른 공개 글이 참조하면 그 파일은 계속 공개된다. 따라서 편집 화면에서 파일의 공개 사용처를 보여준다. 게시 중단·재게시 때 서버/CDN 캐시도 갱신한다. 이미 다운로드된 파일을 회수할 수 있다고 안내하지 않는다.

## 5. 첫 화면 구현 순서

1. M01 로그인과 두 역할의 서버 권한 기반 구성.
2. M03~M04 공지 목록·편집, 첨부·초안 저장.
3. M06 로그인 상태의 미리보기와 게시 전 검증.
4. P05~P06 공개 목록·검색·상세·다운로드.
5. 수정 리비전·게시 중단·복원·동시 수정과 실패 상황.
6. 동일 패턴으로 자료실·고정 페이지, 이후 계정·설정·운영 화면 확장.

처음부터 전체 메뉴 화면을 채우기보다 [A01~A02](first-delivery.md)의 실제 저장·게시 흐름을 먼저 연결한다. 미구현 메뉴를 동작하는 기능처럼 노출하지 않는다.

## 6. 설계 검증 시나리오

| ID | 확인 | 기대 결과 |
| --- | --- | --- |
| R01 | 담당자가 설정·계정·기록 URL과 API 직접 호출 | 화면 및 서버에서 권한 거부 |
| R02 | 비로그인 상태에서 초안 미리보기·첨부 직접 요청 | 내용·파일 비노출 |
| R03 | 다른 담당자가 만든 글 수정 | 첫 범위의 공동 관리 정책대로 허용, 수정자 기록 |
| R04 | 마지막 활성 관리자 강등·비활성화 | 서버 거부, 해결 방법 안내 |
| R05 | 작성 중 계정 비활성화 후 저장·게시 | 요청 거부, 재인증 안내, 데이터 자동 공개 없음 |
| R06 | 게시글 수정 저장 후 공개 조회 | 수정 초안 대신 기존 게시본 반환 |
| R07 | 글 삭제·복원 후 공개 조회 | 휴지통·복원 초안 모두 비공개 |
| R08 | 게시된 페이지를 메뉴에서만 숨김 | 메뉴에서만 사라지고 직접 조회 가능 |
| R09 | 보호 페이지 삭제·참조 중 파일 삭제 요청 | UI 안내 및 서버 거부 |
| R10 | 새 리비전 게시 후 이전 첨부 요청 | 다른 공개 참조가 없으면 차단, 캐시도 검증 |

위 R01~R10은 새로 정의한 검증 항목이며 아직 실행하지 않았다. 문서 링크 검사는 기능·접근성·보안 검증 결과를 대신하지 않는다.

## 7. 다음 산출물
