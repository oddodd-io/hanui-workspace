# 첫 납품 범위와 합격 기준

작성일: 2026-09-21
상태: **대상은 확정 / 상세 범위와 내부 출고 기준은 제안 초안 / 검증 전**

## 1. 누구에게 무엇을 파는가

**대상: 소규모 공공기관 대표 홈페이지** — 사용자 선택으로 확정.

KRDS와 웹접근성을 반영한 기관 홈페이지, 담당자가 직접 콘텐츠를 운영하는 CMS, 설치·운영 문서와 검증 기록을 하나의 납품 패키지로 제공한다. 초기에는 기관별로 설치하는 단일 사이트 구성을 제안한다.

- 방문자: 기관·사업 정보를 읽고 공지사항과 자료를 찾아본다. 공개 회원가입 없이 이용한다.
- 기관 콘텐츠 담당자: 게시글과 고정 페이지 내용을 작성·수정·게시한다.
- 기관 관리자: 담당자 계정·권한과 기본 사이트 설정을 관리한다.
- 납품·운영 개발자: 기관별 초기 구성, 배포, 백업·복구와 업데이트를 담당한다.

최초 검증 제품은 한국어 단일 사이트, 기본 테마 1종, PC·모바일 대응으로 제한한다. 기관별 독립 데이터·설정을 사용한다. 다기관 SaaS는 첫 범위에 넣지 않는다.

## 2. 기술 및 설계 전제

- 백엔드: **전자정부 표준프레임워크 v5 확정**. 정확한 릴리스와 호환 환경은 적용 전에 고정한다.
- 프론트엔드: Vue 중심 방향으로 검증한다. 앱 구성과 기존 Next.js CMS 이식 범위는 미확정이다.
- 개발자가 페이지 구조와 허용된 콘텐츠 블록을 설정하고 담당자는 그 안에서 내용을 편집한다.
- 저장은 실제 백엔드·DB로 검증한다. mock·localStorage 기반 데모는 납품 완료로 보지 않는다.
- 기존 PostgreSQL·MyBatis 기획은 출발점으로 사용하며, 실제 호환성과 납품 환경을 확인한다.

## 3. 첫 버전에 포함할 기능 — 제안

| ID | 기능 | 범위 | 완료를 확인하는 방법 |
| --- | --- | --- | --- |
| F01 | 공통 공개 화면 | 헤더·메뉴·푸터·현재 위치·본문 바로가기·모바일 메뉴 | 키보드로 모든 메뉴와 본문에 접근하고 이동 후 현재 위치를 알 수 있음 |
| F02 | 홈페이지 | 기관 소개 요약, 주요 서비스 링크, 최근 공지. 자동 회전 배너는 제외 | 실제 게시한 공지가 반영되고 모든 링크가 유효함 |
| F03 | 고정 페이지 | 기관 소개·사업 안내·이용 안내·정책 페이지. 고정 템플릿에서 내용 편집 | 담당자가 내용 수정 후 게시할 수 있고 레이아웃·제목 구조가 유지됨 |
| F04 | 게시판 | 공지·자료실을 같은 게시판 유형으로 구성. 목록·제목 검색·페이지 이동·상세·첨부 다운로드 | 검색·페이지 이동·상세 복귀가 일관되고 비공개 글이 노출되지 않음 |
| F05 | 관리자 로그인 | 운영자가 발급한 계정, 로그인·로그아웃·세션 만료·비밀번호 변경 | 로그아웃·계정 비활성화 후 API 접근 차단, 만료 시 안내 및 재로그인 가능 |
| F06 | 계정과 권한 | 기관 관리자·콘텐츠 담당자 2개 역할. 게시판별 세부 권한은 후속 | 담당자가 계정·보안 설정 API를 직접 호출해도 거부됨 |
| F07 | 콘텐츠 관리 | 글·고정 페이지의 초안 저장·미리보기·게시·게시 중단·수정·휴지통·복원 | 아래 상태 규칙과 시나리오 A01~A04 통과 |
| F08 | 제한된 편집기 | 제목·문단·목록·링크·이미지·단순 표. 임의 HTML·스크립트·iframe 삽입 제외 | 이미지 대체텍스트·표 머리글 입력 지원, 붙여넣기 정리, 키보드로 편집 가능 |
| F09 | 파일 관리 | 이미지·문서 업로드·첨부·다운로드, 유형·용량 제한과 사용 중 파일 확인 | 비공개 첨부 직접 URL 차단, 실행 파일 등 비허용 파일 거부, 게시 중 파일 삭제 보호 |
| F10 | 기본 설정 | 기관명·로고·연락처·푸터 정보·메뉴명/순서/표시. 페이지 템플릿 추가는 개발자 작업 | 설정이 공개 화면에 반영되고 미게시 페이지 메뉴는 방문자에게 숨김 |
| F11 | 변경 기록 | 로그인·권한 변경·게시·수정·삭제·복원의 수행자·시각·대상 기록 | 관리자가 이력을 확인하며 비밀번호·토큰 등은 기록에 포함되지 않음 |
| F12 | 오류·안내 | 빈 결과·404·권한 없음·저장 실패·연결 끊김·세션 만료 | 상태를 이해하고 재시도·복귀할 수 있으며 입력 내용이 예고 없이 사라지지 않음 |
| F13 | 설치·운영 | 환경 설정, 초기 관리자 발급, DB·파일 백업과 복구, 업데이트·되돌리기 안내 | 별도 환경에서 문서대로 설치하고 백업을 복구해 주요 흐름 재현 |

첨부 파일의 초기 제안: 이미지 PNG/JPEG/WebP, 문서 PDF/HWP/HWPX/DOCX/XLSX, 파일당 최대 20MB. 서버에서 유형·용량을 확인하고 최종 허용 목록은 기관 정책에 맞춰 고정한다. 문서 다운로드와 문서 내부 접근성은 별개로 점검한다.

### 콘텐츠 상태 규칙

- 초안: 방문자 목록·검색·상세 API·첨부 URL에서 접근할 수 없다. 미리보기는 권한 있는 담당자만 본다.
- 게시: 게시된 리비전만 공개된다. 수정 초안을 저장해도 기존 게시본은 유지된다.
- 재게시: 검증된 수정본으로 공개 리비전을 교체한다. 실패하면 기존 게시본을 유지한다.
- 게시 중단: 공개 조회와 관련 파일의 공개 접근을 차단한다. 공유 파일은 다른 게시물의 공개 사용 여부에 따라 처리한다.
- 휴지통: 공개되지 않는다. 복원 시 초안으로 돌아가며 자동 재게시하지 않는다.
- 동시 수정: 오래된 버전의 저장은 충돌로 안내하고 다른 사람의 변경을 조용히 덮어쓰지 않는다.

## 4. 첫 버전 이후로 미룰 기능

- 공개 회원가입, 민원·신청·예약·결제, 본인확인과 외부 업무 시스템 연계
- 승인 결재, 예약 게시, 다국어, 다기관 SaaS, 자유로운 페이지 빌더
- AI 글쓰기, 고급 통계·성과보고서, 전용 HWP/PDF 뷰어, 복잡한 표·차트
- 모든 KRDS 컴포넌트의 일괄 구현, React·Vue 동시 기능 확장

첫 기관에서 필수로 요구하면 범위·비용·일정을 별도로 반영한다. 기존에 화면이 있다는 이유로 첫 납품 필수 기능에 포함하지 않는다.

## 5. '합격'의 의미

아래 기준은 **HANUI의 내부 출고 기준 제안**이다. 공식 KRDS 점수나 인증기관의 합격률을 임의로 정한 것이 아니다.

| 단계 | 판정 |
| --- | --- |
| 내부 제품 출고 | 아래 G01~G07의 필수 항목과 대상 기능 시나리오가 모두 통과하고 미확인 항목이 없음 |
| 기관별 납품 검수 | 내부 출고 후 해당 기관 콘텐츠·설정·환경으로 재검증하고 제안요청서·계약의 추가 기준 충족 |
| 외부 웹접근성 인증 | 요구되면 지정된 인증기관의 별도 심사 결과로 판단. 자체 검사 결과로 인증 취득을 표시하지 않음 |

KRDS 공식 안내는 자체 검증 체크리스트와 세부 기준·도구를 통한 준수 여부 확인을 설명한다. [KRDS 정부 관계자 안내](https://www.krds.go.kr/html/site/outline/outline_04.html)

웹접근성 점검 기준선은 KWCAG 2.2로 제안한다. 한국정보접근성인증평가원은 2025년 1월 신청부터 KWCAG 2.2 심사지침 적용을 안내한다. 실제 인증 신청 시 해당 기관의 최신 지침과 대상 범위를 다시 확인한다. [심사 기준 변경 안내](https://wa.or.kr/board/view.asp?BoardID=0001&SearchString=&cate=&page=1&search=&sn=32749)

### G01 · 기능과 데이터

- F01~F13 및 A01~A08 전부 통과. 데이터 손실·비공개 정보 노출·주요 업무 불능 결함 0건.
- 저장 후 새로고침·재로그인·서버 재시작에도 저장한 콘텐츠 유지.
- 공개 HTML·API·검색·첨부 파일 모두 같은 공개 상태와 권한 규칙 적용.

### G02 · KRDS

- 사용할 가이드·체크리스트의 정확한 판본·발행일·출처·확보일을 고정하고 점검표에 연결한다. 저장소 README에 적힌 버전만으로 확정하지 않는다.
- 적용 대상인 필수 항목은 모두 통과. 권장 항목은 적용 여부와 이유를 기록하며, 발주 기준상 필수이면 필수로 취급한다.
- 색상·글꼴·간격뿐 아니라 메뉴·목록 탐색·상세·폼·오류 패턴까지 실제 화면에서 확인한다.
- 기관 로고·색상으로 변경한 뒤 다시 점검한다. 비해당 항목은 이유와 검토자를 기록한다.
- Checker 자동 점검, 수동 시각·동작 점검을 구분한다. 아직 구현되지 않은 검사 항목을 통과로 처리하지 않는다.

### G03 · 웹접근성

- 공개 사이트와 관리자 주요 업무 모두 내부 검증 대상이다. 공개 사이트만 통과하고 담당자의 편집 화면은 제외하는 방식으로 완료하지 않는다.
- 기준선의 적용 항목을 점검표에 전부 매핑한다. 자동 검사 확인 오류 0건, 수동 검사 대상 항목 전부 통과. 도구의 미확정 결과·오탐도 근거를 기록해 해소한다.
- 키보드만으로 탐색·검색·편집·게시 가능. 초점 표시·순서·복귀, 입력 레이블·오류 안내, 상태 변화 전달 확인.
- 스크린리더로 메뉴·게시글·표·폼 의미와 작업 결과 확인. 확대·모바일에서 정보·기능 누락 없음.
- 납품 콘텐츠의 대체텍스트·제목 구조·링크 설명·표 구조를 포함해 확인. 이미지형 공지에는 동등한 텍스트 정보를 제공한다.
- 문서 내부 접근성은 별도 수동 확인 항목으로 남기고, 필요한 정보는 접근 가능한 본문으로도 제공한다. 파일 업로드 성공을 접근성 통과로 보지 않는다.
- 편집기는 대체텍스트 누락 등 기계적으로 확인 가능한 오류를 게시 전에 알리고 차단한다. 내용의 적절성은 담당자 수동 체크와 교육으로 보완한다.

### G04 · 인증·권한과 입력 처리

- 미로그인·담당자·관리자로 동일 API를 호출해 권한 경계 확인. 서버에서 모든 쓰기·미리보기·파일 접근 검사.
- 비밀번호 안전한 해시 저장, 기본 계정 비밀번호 강제 변경, 로그인 시도 제한, 세션 만료·무효화 확인.
- 사용자 HTML·파일·검색 입력에 대한 서버 검증, XSS·SQL 주입 방어, 인증 방식에 맞는 CSRF 방어 확인.
- 환경별 비밀값 분리, 운영 오류 응답에서 내부 정보 숨김, 사용 의존성의 알려진 취약점 점검.
- 악용 가능한 인증 우회·데이터 노출·코드 실행 결함은 출고 차단. 도구 경고는 적용 가능성과 처리 결과를 기록.

### G05 · 설치·복구·운영

- 지원 OS·JDK·DB·프레임워크·배포 방법을 버전까지 고정. 깨끗한 환경에서 문서대로 설치 성공.
- DB와 첨부 파일을 함께 백업하고 별도 환경에서 복구. 대표 게시글·권한·첨부를 대조해 일치 확인.
- 업데이트 실패 시 이전 버전·데이터로 되돌리는 절차 검증. 로그 위치·장애 확인·복구 담당 역할 명시.
- 백업 주기, 보관 기간, 복구 시간 목표와 유지보수 범위는 첫 기관 환경 확정 시 기록하며 납품 전 빈칸을 해소.

### G06 · 브라우저·반응형·성능

- 초기 내부 조합: Windows Chrome/Edge/Firefox, macOS Safari, Android Chrome, iOS Safari. 검사 당시 OS·브라우저 버전 기록.
- 보조기술 최소 조합: Windows NVDA+Chrome, iOS VoiceOver+Safari. 외부 심사 요구 조합은 별도 추가.
- 공개·관리자 모두 360/768/1280 CSS px와 200% 확대에서 주요 업무 완료. 320 CSS px 및 400% 확대에서 재배치 확인; 표 등 예외는 해당 기준에 따라 개별 기록.
- 성능은 시험 서버 사양·네트워크·DB 규모·동시 사용자·측정 방법을 먼저 고정한다. 초기 검증 제안값은 게시글 1만 건, 공개 조회 동시 사용자 20명, 5분 측정 시 읽기 API p95 1초 이하·5xx 0건이다. 공식 기준이나 실제 납품 용량 보장이 아니다.
- 성능 조건과 결과가 미확정이면 제품 성능 합격을 선언하지 않는다. 첫 기관 예상 부하가 더 크면 기준을 갱신한다.

### G07 · 인수인계와 증빙

## 7. 점검표와 출고 판정 방법

각 결과는 `기준 ID / 공식 항목 ID·출처 / URL·화면 상태 / 데이터·권한 / 시험 환경 / 자동·수동 구분 / 결과 / 증빙 / 결함·재검증 / 검사자·일시`를 남긴다.

결과는 통과·실패·미확인·비해당으로 기록한다. 필수 검증의 실패나 미확인이 남으면 출고 보류. 비해당에는 이유가 필요하다. 필수 기준 외 경미한 개선은 영향·처리 계획을 남기되, 이를 이용해 필수 미충족을 통과 처리하지 않는다.

범위와 기준을 확정한 뒤 실제 시험 결과는 별도 기록한다. 현재 모든 구현·검증 결과는 미확인이며, 이 문서 작성은 제품 합격을 뜻하지 않는다.
