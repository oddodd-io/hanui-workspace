# HANUI 공공 웹 구축 프로젝트

## 사업 목적

정부·공공기관 웹사이트 구축 입찰에 참여하고, KRDS 디자인 가이드와 웹접근성을 반영한 사이트를 구축·납품·운영할 수 있는 기반을 만든다.

이를 위해 재사용 컴포넌트인 **HANUI**, 이를 기반으로 기관 사이트를 구축하고 운영하는 **HANUI CMS**, 완성된 사이트의 KRDS 준수 여부를 점검하는 **KRDS Checker**를 함께 개발한다.

이 문서는 여러 저장소에 흩어진 사업 의도와 프로젝트 간 관계를 정리한 기준 문서다. 아래 목적은 2026-09-21 프로젝트 소유자가 설명한 의도를 기준으로 한다. 기능의 구현 완료나 검수 통과를 의미하지 않는다.

## 왜 만드는가

공공기관 사이트를 만들 때 KRDS 가이드를 매번 개별 화면으로 구현하고, 웹접근성을 챙기는 작업이 반복된다. 납품 시에는 완성된 사이트가 실제로 KRDS를 따르는지 확인하는 검수에도 대응해야 한다.

따라서 컴포넌트 제작, CMS 구축, 결과물 점검을 하나의 흐름으로 연결한다. 반복 개발을 줄이고, 기관 담당자가 운영할 수 있는 제품을 납품하며, 준수 여부를 확인하고 보완할 수 있도록 하는 것이 목적이다.

기존 기획에는 초기 대상으로 소규모·무응찰 공공기관 입찰이 언급돼 있다. 전체 사업 목적은 정부·공공기관 웹 구축이며, 구체적인 입찰 대상과 범위는 개별 사업에서 정한다.

## 세 프로젝트의 역할

| 프로젝트 | 만드는 것 | 사업에서의 역할 |
| --- | --- | --- |
| [HANUI](../hanui/README.md) | KRDS 기반 컴포넌트·디자인 토큰, CLI, 문서 | KRDS와 웹접근성을 반영한 공통 구현을 재사용해 사이트 구축의 기반으로 사용 |
| [HANUI CMS](../hanui-cms/README.md) | HANUI 기반 공개 사이트와 관리자 시스템 | 기관별 사이트를 구축·납품하고 담당자가 콘텐츠를 직접 운영하도록 지원 |
| [KRDS Checker](../krds-checker/README.md) | 완성된 사이트의 KRDS 준수 여부를 점검하는 도구 | 구축 중 문제를 찾고 수정하며 납품 검수에 대응 |

```text
KRDS 디자인 가이드 + 웹접근성 요구사항
                  ↓ 구현
                HANUI
                  ↓ 재사용
              HANUI CMS
                  ↓ 기관별 구축·납품
             공공기관 웹사이트
                  ↓ 점검
             KRDS Checker
                  ↓ 발견한 문제 반영
       사이트·CMS·공통 컴포넌트 개선
```

Checker는 완성된 사이트를 점검하는 역할이며, HANUI 전용 검사기로 범위를 한정하지 않는다. 위 화살표는 사업 흐름을 나타내며, 모든 단계가 코드나 API로 연결됐다는 뜻은 아니다.

## 제품 방향

- **HANUI:** KRDS와 웹접근성을 고려한 공통 컴포넌트를 제공한다. CMS와 문서 사이트에서 재사용하고, 공통 문제는 라이브러리 개선으로 반영한다.
- **CMS:** 개발자가 납품 시 디자인과 레이아웃을 설정하고, 기관 담당자는 콘텐츠를 직접 관리하는 구조를 지향한다. 기존 기획의 인라인 편집, 접근성 검사, 성과보고서 생성 등은 이 목적에 따른 기능 후보·계획이다.
- **Checker:** 실제 결과물을 기준으로 KRDS 준수 여부와 보완할 항목을 확인하는 도구를 지향한다. 전체 사업의 품질 기준에는 웹접근성도 포함되며, Checker의 구체적인 접근성 검사 범위와 구현 상태는 별도로 확인한다.

컴포넌트 사용 여부와 완성된 사이트의 준수 여부는 각각 확인한다. 검사 도구의 결과도 자동으로 확인한 항목과 사람이 확인해야 할 항목을 구분해 검수에 활용하는 방향으로 설계한다.

## 개발 방향

Vue 중심으로 개발 역량을 집중하는 방향을 검토한다. 배경과 결정 상태는 [기술 선택 기록](decisions.md)에서 관리한다. 현재 React 기반 CMS의 구현 상태와 앞으로 선택할 기술을 구분한다.

백엔드는 사용자 지정에 따라 **전자정부 표준프레임워크 v5**를 사용한다. 구체적인 릴리스와 적용 상태는 [기술 선택 기록](decisions.md) 및 [할 일](tasks.md)에서 관리한다.
