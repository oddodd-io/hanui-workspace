## 접근성

- [ ] **`aria-expanded`를 두 군데 지정하면 생기는 일** — 부모 행과 자식 토글 아이콘에 각각 붙였을 때 스크린리더 탐색 모드에서 초점 이동이 어긋나는 문제. 하나만 남겨야 하는 이유.
- [ ] **팝오버가 닫힐 때 포커스를 어디로 돌려보낼 것인가** — body로 떨어지면 키보드 사용자가 처음부터 다시 Tab. 트리거로 되돌리는 훅 패턴과, 트리거가 사라진 경우의 처리.
- [ ] **"새 창에서 열립니다" 안내를 잘못 붙이면 더 나쁘다** — 외부 링크용 아이콘·안내를 내부 링크에도 재사용했을 때 생기는 오안내. `rel="noopener noreferrer"`는 어디까지 필요한가.
- [ ] **클릭되는 건 전부 button이어야 하나** — div에 onClick 달린 필터 트리거를 button으로 바꾸고 포커스 트랩까지 거는 과정.
- [ ] **링크냐 버튼이냐 결정표** — 외부/내부 × 텍스트/버튼 네 조합에서 무엇을 `<a>`로 하고 무엇을 `<button>`으로 할지. 헷갈릴 때 보는 표 만들기.

## 성능

- [x] **`React.memo`가 안 듣는 가장 흔한 이유** → [react-memo-stable-callback](https://hanui.io/blog/react-memo-stable-callback) (2026-08-13), 후속 [data-table-memo-shipped](https://hanui.io/blog/data-table-memo-shipped) (2026-09-15) — 큰 트리·리스트에서 행을 memo로 감쌌는데 여전히 다시 그려질 때. 인라인 콜백과 객체 prop이 memo를 무력화하는 구조.
- [ ] **개수만 필요한데 목록을 다 받아오고 있진 않나** — 탭 배지 숫자 때문에 전체 목록을 조회하던 걸 `size=1`로 줄이기. 서버 페이징 API에서 흔한 낭비.
- [ ] **컴포넌트별 코드 분할 + `sideEffects` 선언** — 라이브러리를 쓰는 쪽이 안 쓰는 컴포넌트를 안 받게 하는 두 가지 조치. ※ [hanui 글](https://hanui.io/blog/bundle-size-six-months-later)에서 "아직 안 했다"고 쓴 부분이라 후속편으로 이어짐

## 구조·리팩터링

- [ ] **거대해진 화면을 쪼개는 기준** — 대시보드/모달 한 파일이 수백 줄이 됐을 때 state / data / columns 훅으로 가르는 기준선. "언제 쪼갤지"보다 "어디를 그을지"가 어려움.
- [ ] **React Query 무효화를 rootKey 하나로** — 쿼리키를 팩토리로 만들고 루트 키로 한 번에 무효화하기. 중복 refetch가 이미 커버되는 걸 모르고 또 부르는 문제.
- [ ] **CSP 때문에 인라인 스타일을 걷어낸 이야기** — 왜 막히는지, 라이브러리가 강제하는 인라인 스타일은 어떻게 예외 처리하는지.
- [ ] **`Set`을 쓸까 배열을 쓸까** — 배열로 변환해가며 처리하던 걸 Set add/delete로 바꿨을 때 실제로 나아지는 것과 안 나아지는 것.

## 버그·엣지케이스

- [ ] **숫자 입력에서 `-`만 쳤을 때** — 연산자만 입력된 중간 상태를 어떻게 다룰지. `NaN` 반환 vs 이전 값 유지 vs 빈 값. 소수점 지원까지 붙이면 경우의 수가 늘어남.
- [ ] **캘린더에서 일요일을 빨갛게 칠하는 게 맞나** — 하드코딩된 요일 색상이 지역·문화 설정과 충돌하는 문제.
- [ ] **중복 토스트 막기** — 업로드 완료 알림이 두 번 뜨는 전형적 원인(낙관적 업데이트 + 서버 응답 양쪽에서 발생).
